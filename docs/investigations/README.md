# Investigations

Three investigations on the pipeline's data, each answering an engineering question with statistics or machine learning (REQUIREMENTS.md section 3b).

| ID | Question | Report |
| --- | --- | --- |
| I1 | Which network constraints bind most often in SA, and what drives them? | `I1-binding-constraints.md` |
| I2 | How often is the Heywood interconnector at its limit, and under what conditions? | `I2-heywood-limits.md` |
| I3 | Is the SCADA data trustworthy? | `I3-scada-quality.md` |

## How the reports are made

Every number, table and figure in a report is generated by `sagrid investigate` from the DuckDB store. Nothing is edited by hand. Each report starts with a snapshot table listing the rows and a content hash for every input table in the window, plus the code commit. Running the same command on the same data reproduces the report exactly, and a changed hash shows the data is different.

```powershell
pip install -e ".[analysis]"          # scikit-learn, scipy, matplotlib (included in .[dev])
sagrid investigate all --start 2026-10-19 --end 2026-10-25
```

Each run writes, for every investigation:

- `<ID>.md`: the report (question, data, method, findings, limitations, recommended response)
- `<ID>.json`: every number in the report, for checking or reuse
- `<ID>/`: figures (PNG) and the full tables (CSV), including I3's issues register
